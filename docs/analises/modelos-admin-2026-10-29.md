# Nome técnico compartilhado entre versões — 29/10/2026

O usuário observou que a busca deixou de usar o servidor do modelo após o cadastro da URL no admin. Dentro de `chateau_orchestration`, `http://host.docker.internal:11435/api/tags` respondeu HTTP 200; `:11434` recusou conexão. Os logs da API mostraram buscas ainda em `http://127.0.0.1:11434`, endereço que aponta para o próprio container, e duas tentativas de atualização recusadas por unicidade de `AiModel.modelName`. O usuário esclareceu que havia editado outra versão, a Pro, e que o admin deve permitir o mesmo nome técnico em versões diferentes.

Decisão: remover a unicidade do nome técnico; manter único o Nome de exibição. O chat envia o ID do cadastro selecionado e o nome técnico. O backend obtém a URL pelo ID, verifica disponibilidade e correspondência do nome, e envia à orquestração o nome técnico e a URL desse cadastro. Chamadas antigas só com o nome técnico continuam aceitas se um único cadastro disponível usar o nome. O histórico novo guarda o ID para repetir a mesma versão; histórico anterior sem ID usa a seleção atual correspondente ou a versão mais alta disponível.

Implementado no Expert em 29/10: migração Prisma, API, chat e testes. Commit `8000529` enviado a `main` por autorização do usuário. O push aciona o workflow de deploy; a conclusão do deploy e a busca com o servidor do modelo ainda não foram verificadas. Após o deploy, o administrador precisará salvar na versão Pro `http://host.docker.internal:11435`, marcar Disponível e testar a busca real. O HTTP 200 em `/api/tags` comprova conectividade, não geração de resposta pelo modelo.
