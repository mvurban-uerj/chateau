# Contrato da busca

**Estado implementado localmente no Expert em 04/11/2026; deploy e servidores de modelo reais ainda não validados.** O web envia `POST /api/search` com `{pergunta, modelId?, modelName?}`. A rota Next.js acrescenta o token interno e o e-mail da sessão em `X-User-Email`. A API exige usuário autorizado e autorização de contexto; limita a pergunta a 1.000 caracteres. Sem modelo selecionado, usa mock. Com modelo selecionado, confere que o cadastro por ID está disponível e que seu nome técnico corresponde ao enviado. Uma chamada legada apenas com `modelName` só é aceita quando há um único cadastro disponível com esse nome. O histórico conserva ID e nome para repetir a busca.

O Admin guarda URLs ordenadas por cadastro. A API resolve essa lista no banco e chama `POST /search` na orquestração com pergunta original, usuário, `modelo`, `ollama_urls`, `ollama_url` (primeira URL, para compatibilidade) e `prompt_contract`. O navegador nunca envia URLs nem formato de prompt. O backend determina `prompt_contract` pelo nome técnico: `chateau-gemma4-e4b-cypher` → `e4b`; `chateau-data-gemma4-31b-cypher-rev6-2000-A-s1234` → `rev6_31b`. Nome sem correspondência recebe erro 400. `ORCHESTRATION_URL` só substitui o endereço interno da orquestração, `http://orchestration:8000` por padrão.

**Failover sequencial, sem distribuição normal de carga:** a orquestração tenta a primeira URL e avança na ordem do cadastro quando há falha de conexão antes da resposta, HTTP 503 ou resposta técnica vazia do modelo. Todas as tentativas compartilham o prazo de 55 s do modelo; cada URL recebe apenas o tempo restante. Ela não troca de URL por timeout de geração, outro erro HTTP, recusa explícita `RETURN null AS sem_resposta`, consulta sem linhas ou erro no Neo4j. Se as URLs falham, aplica-se a resposta simulada vigente para falha de modelo. Quarkus e Python registram no log de cada busca todas as tentativas de chamada ao modelo, inclusive com uma URL e em falha: horário, URL, tempo decorrido, desfecho e contagens de tokens quando disponíveis. O limiar de lentidão, a capacidade dos servidores, distribuição normal de carga, afinidade por conversa e política de timeout continuam pendentes de decisão e teste real. [Contexto da decisão](../../docs/analises/failover-modelo-2026-11-04.md) e [decisão de medição](../../docs/analises/medicao-latencia-modelo-2026-11-04.md).

**Modelo orquestrador, implementação local de 05/11/2026; deploy e modelo real não validados.** O web pode enviar `historico` (até 20 itens) com as trocas anteriores da conversa aberta. Com o modelo orquestrador ligado no Admin e um modelo Cypher selecionado, a API reduz o histórico (4 trocas, 15 linhas, células de 120 caracteres, cerca de 8.000 caracteres, descartando as mais antigas; resposta simulada vai só com a pergunta). Envia ao Quarkus `orquestrador: {url, modelo}` e `historico` e soma 20 s ao seu timeout. Desligado, o histórico é descartado e o corpo é o anterior. Havendo histórico, o Quarkus chama `/api/generate` do modelo orquestrador com instrução fixa, conversa e pergunta atual, `think: false` e prazo de 20 s. A pergunta reescrita substitui a original somente na chamada ao modelo Cypher. Falha ou resposta vazia mantém a pergunta original. A resposta, o log JSONL e o `SearchResult` (`fluxo`) trazem desfecho (`reescreveu`, `sem_historico` ou `falhou`), prompt enviado, pergunta original, pergunta gerada, tempo e tokens. **Divergência registrada:** o Python ignora `orquestrador` e `historico` e se comporta como desligado. [Plano e limitações acordadas](../../docs/integracao-modelo/plano-modelo-orquestrador.md#9-limitações-acordadas-da-fase-1-05112026).

Quarkus é a implementação padrão; Python é a reserva de comparação. Com `e4b`, o cliente de `/api/generate` envia `system` montado com `CHATEAU_SCHEMA_ARQUIVO` e a pergunta em `prompt`. Com `rev6_31b`, envia o template integral rev_6 em `prompt`, sem `system`, com `think: false`. O template inclui entidades ainda sem registros no Neo4j. `RETURN null AS sem_resposta` é interceptado antes da consulta e classificado como `fora_escopo`. O servidor do modelo é tratado como caixa preta: esta descrição cobre apenas a requisição construída e a resposta recebida, sem presumir seu processamento interno.

O serviço responde com `cypher`, `avisos`, `tokens_prompt`, `segundos`, `resultado`, `recusada` e `erro`, inclusive nas falhas de modelo ou banco; requisição inválida recebe 422. A API devolve `status`, `mensagem`, `cypher`, `avisos`, `colunas`, `linhas`, `truncado` e `tempoMs`. O limite padrão é 50 linhas, máximo 500. Antes de executar Cypher, Python e Quarkus usam `EXPLAIN` e só aceitam leitura; a transação também é somente leitura e tem timeout. Erro no Neo4j vira `erro_consulta`; resultado vazio ou só com células vazias vira `sem_resultado`. Falha de transporte entre API e orquestração ou falha do modelo produz resposta simulada com aviso.
