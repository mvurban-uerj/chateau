# Operação e validação

**Referência dos comandos versionados; não indica estado vivo de servidores.** O Expert roda localmente pelo [docker-compose.yml](../../chateau-expert/docker-compose.yml) e define produção em [docker-compose.prod.yml](../../chateau-expert/docker-compose.prod.yml). Ambos usam Caddy, web, API e PostgreSQL. A orquestração sobe sempre em produção; no ambiente local, o perfil `ia` adiciona a orquestração e o Neo4j de exemplo. Sem modelo disponível, a busca usa mock. `ORCHESTRATION_URL` só substitui o endereço interno padrão da orquestração. O Neo4j guarda o grafo e o PostgreSQL guarda o estado da aplicação.

- O [workflow de deploy](../../chateau-expert/.github/workflows/deploy.yml) dispara no push para `main` de `chateau-expert`, roda build/testes do backend com PostgreSQL e da web, verifica espaço em disco e atualiza o servidor via SSH/Compose. Ele usa `git reset --hard origin/main` no checkout do servidor; alterações locais lá não são preservadas. O deploy compara com o último commit concluído para reconstruir apenas serviços alterados. O workflow não valida o Data nem as duas implementações da orquestração no mesmo gate.
- Testes de integração do backend: `npm --prefix chateau-expert run test` a partir da raiz deste workspace (o script do Expert cria/usa um PostgreSQL de teste em container). Testes unitários/integração usam Vitest; [instruções](../../chateau-expert/backend/scripts/test-integration.sh).
- O Data usa `python3 -m unittest discover -s tests -v` a partir de `chateau-data/scripts`; parte da suíte consulta a API Sucupira e depende da rede. [Guia](../../chateau-data/scripts/tests/README.md). O teste de extração PDF tem [falha confirmada](../dados/fontes-e-pipeline.md).
- A orquestração Python tem testes `pytest`; a Quarkus tem testes Maven com Neo4j de teste via Dev Services. A [comparação](../../chateau-expert/orchestration/README.md) verifica a equivalência do contrato HTTP entre implementações.
- O schema usado pelo modelo texto→Cypher pode ser comparado com o Arrows e o Neo4j por [comparar_com_modelo.py](../../chateau-expert/orchestration/schema/comparar_com_modelo.py). A extração do schema de produção é um procedimento separado, descrito em [orchestration/schema](../../chateau-expert/orchestration/schema/); não assumir que o arquivo versionado reflita o servidor no momento da tarefa.

Segredos ficam em `.env`/`.env.prod` fora do Git; o [template](../../chateau-expert/.env.example) lista as variáveis. `INTERNAL_API_TOKEN` (mesmo valor para web e API, ≥ 32 caracteres) é obrigatório: sem ele a API encerra na inicialização. Ele precisa existir no `.env.prod` do servidor **antes** do deploy que introduz a autenticação web → API. Nunca registrar valores reais em documentação de domínio.
